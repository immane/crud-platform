    钱包捆绑设计¶

    钱包包 (src/Wallet/) 提供用户钱包、交易和原子 具有防止死锁和幂等性的钱包到钱包转账。

    1. 概述¶

    钱包是一个用于管理用户余额的金融模块：

    • 钱包 每个用户每种货币的余额以美分为单位，乐观锁定和冻结功能
    • WalletTransactions 具有 UUID、类型分类、状态跟踪和幂等性（通过 referenceId）
    • TransferService 具有钱包到钱包的原子传输、死锁预防和回滚恢复

    1.1 实体¶

    实体 表 目的
    Wallet wallet 每种货币的用户余额（美分）、冻结支持、乐观锁定
    WalletTransaction wallet_transaction 存款/取款/转账/手续费/退款记录

    3.实体设计¶

    3.1 钱包¶

    领域 类型 详情
    id 整数 自增PK
    user 多对一 -> 用户 钱包主人
    currency 字符串 货币代码（例如 CNY、USD）
    balance int（bigint） 余额（分）
    version 整数 #[ORM\Version]乐观锁
    status 字符串 active 或 frozen
    label 字符串 人类可读的钱包名称

    唯一约束：(user_id, currency)——每个用户每种货币一个钱包。

    方法：isActive(): bool、isFrozen(): bool

    3.2 钱包交易¶

    领域 类型 详情
    id 整数 自增PK
    uuid 字符串(32) UUID v4c 供外部参考
    fromWallet ManyToOne -> 钱包（可为空） 源码钱包
    toWallet ManyToOne -> 钱包（可为空） 目的地钱包
    amount int（bigint） 金额（美分）
    type 字符串 deposit、withdrawal、transfer、fee、refund
    status 字符串 pending、completed、failed、reversed
    referenceId 字符串（唯一） 幂等性密钥
    description 字符串 人类可读的注释
    metadata JSON 可扩展数据

    唯一约束：referenceId——防止重复交易。

    方法：markCompleted()、markFailed()

    4. TransferService——原子传输¶

    4.1 合同¶

    interface TransferServiceInterface
{
    /**
     * @param int|string $fromWalletId  Source wallet ID
     * @param int|string $toWalletId    Destination wallet ID
     * @param int        $amount         Amount in cents
     * @param string     $referenceId    Idempotency key (unique)
     * @param string     $description    Human-readable note
     * @return TransferResult
     * @throws InsufficientFundsException
     * @throws WalletFrozenException
     * @throws SameWalletTransferException
     */
    public function transfer(
        $fromWalletId,
        $toWalletId,
        int $amount,
        string $referenceId,
        string $description = ''
    ): TransferResult;
}

    4.2 传输算法¶

    transfer(fromWalletId, toWalletId, amount, referenceId, description)
  |
  v
1. Idempotency Check
   -> Query existing transaction by referenceId
   -> If found and completed: return existing TransferResult
   -> If found and not completed: reject (duplicate in-flight)
  |
  v
2. Lock Wallets (Deadlock Prevention)
   -> Sort wallet IDs ascending
   -> SELECT ... FOR UPDATE on both wallets (in sorted order)
   -> This guarantees consistent lock ordering across concurrent transfers
  |
  v
3. Validation
   -> fromWallet != toWallet (SameWalletTransferException)
   -> fromWallet->isFrozen() || toWallet->isFrozen() (WalletFrozenException)
   -> fromWallet->getBalance() >= amount (InsufficientFundsException)
   -> Currency match: fromWallet->getCurrency() == toWallet->getCurrency()
  |
  v
4. Create Transaction Record
   -> type = 'transfer', status = 'pending'
   -> referenceId (idempotency key)
  |
  v
5. Execute Transfer (within DB transaction)
   -> beginTransaction()
   -> DQL UPDATE: fromWallet.balance -= amount
   -> DQL UPDATE: toWallet.balance += amount
   -> transaction->markCompleted()
   -> commit()
   |
   -> On failure: rollback(), transaction->markFailed()
   -> EM recovery: if !$em->isOpen(), recreate EM
  |
  v
6. Return TransferResult
   -> Transaction entity + post-transfer balances

    4.3 传输结果 DTO¶

    class TransferResult
{
    public WalletTransaction $transaction;
    public int $fromWalletBalance;  // Post-transfer
    public int $toWalletBalance;    // Post-transfer
}

    5.异常设计¶

    例外 当被抛出时
    InsufficientFundsException 源钱包余额<转账金额
    WalletFrozenException 钱包状态为 frozen
    SameWalletTransferException fromWalletId == toWalletId

    所有异常都扩展\RuntimeException。

    6. API 端点¶

    6.1 管理（管理员、ROLE_ADMIN）¶

    方法 路径 描述
    获取 /api/v1/manage/wallets 列出钱包
    获取 /api/v1/manage/wallets/{id} 钱包细节
    发布 /api/v1/manage/wallets 创建钱包
    放置 /api/v1/manage/wallets/{id} 更新钱包（冻结/解冻）
    删除 /api/v1/manage/wallets/{id} 删除钱包
    获取 /api/v1/manage/transactions 交易列表
    发布 /api/v1/manage/transfer 执行钱包到钱包转账

    7. 乐观锁定合约¶

    钱包使用 #[ORM\Version] 进行乐观并发控制：

    • 在并发更新时，Doctrine 会抛出 OptimisticLockException
    • 调用者应重试或报告冲突
    • 这可以防止 TransferService 外部余额更新的竞争条件

    8. 资金处理合同¶

    与贸易模块相同的合约：

    方面 规则
    存储 bigint（分）
    PHP 类型 int
    API边界 十进制（字符串/数字）
    转账金额 整数分（非小数）
